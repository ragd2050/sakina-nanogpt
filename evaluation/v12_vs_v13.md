# SAKINA v12 → v13 — What actually changed, with evidence

Every claim below was tested during this session; the test is named so it
can be re-run. This builds on `evaluation/archive/v12_comparison.md` (the
v11→v12 history) and `evaluation/v12_evaluation_report.md` (formal v12
A-E evaluation). See `evaluation/v13_evaluation_report.md` for the full
v13 A-G evaluation and `evaluation/v13_run_metadata.json` for exact
checkpoint/dataset versions.

## Before (v12) vs After (v13)

| | v12 | v13 |
|---|---|---|
| Conversation memory | no `pending_clarification` state at all | **real bug found & fixed**: replying "نفسي" to "تعباً جسدياً أم نفسياً؟" was reclassified from zero as **ذنب وتقصير** (wrong) instead of resolving the question. Fixed via `memory.pending_clarification` + `CLARIFICATION_ANSWER_MAP` (verified: `tests/test_sakina.py::TestMemory::test_pending_clarification_resolves_correctly`, section F of the v13 report, 7/7) |
| Quran audio endpoint | untested guess: `/recitations/{id}/by_chapter/{chapter}` | corrected to the brief's own specified working pattern: `/quran/recitations/{id}?chapter_number={n}`, matched on `verse_key`. `/api/audio` response now includes `recitation_id` per the brief's exact schema. **Still untested against the live API** — no network path to `quran.foundation` in this sandbox, in v12 or now |
| Multi-turn conversation data | `data/conversations_dataset.json`, 3,214 records, **shape looked multi-turn but 99.8% (3,209/3,214) were actually single-turn** (audited this pass, was never checked in v12) | new `data/conversations_dataset_v13.json`: **1,798 verified genuine User→Assistant→User→Assistant conversations** (1,088 stable-emotion, 710 emotion-transition), built from real turn-1 examples + reviewed turn-2 follow-ups (`data/multiturn_banks.py`), audited 100% genuine by the same script |
| COMFORT_BANK | 8 lines/emotion (96 total) | 15 lines/emotion (180 total) — within the brief's 15-25/emotion target, hand-written and reviewed, not model-generated |
| nanoGPT | 2200-iter checkpoint from a prior session | **retrained from scratch this session**, same architecture (4L/4H/192d, 1.81M params) and same corpus — final val loss 0.70 (best) / 0.86 (final), consistent with v12's reported 0.87-0.97 range |
| nanoGPT acceptance rate | ~18-23% (n=100, varied by sample) | 22-23% (n=100) — **unchanged within noise** despite the fresh retrain and the larger COMFORT_BANK. This is itself a finding: the ceiling is the 1.8M-param, from-scratch, char-level model, not this data (see Limitations) |
| Automated tests | none | 64 tests across classifier, ambiguity, memory, Quran, audio, quality gate, and the Flask API surface (`tests/test_sakina.py`), all passing |
| Evaluation hygiene | `v12_evaluation_report.md` and its inputs not versioned/timestamped | `evaluate_v13.py` writes `v13_run_metadata.json` (timestamp, checkpoint refs, dataset versions) alongside `v13_evaluation_report.md`; stale v10-era scripts/reports (`evaluate.py`, `quality_eval.py`, `quality_metrics.json`, `comparison_report.md`, `v12_comparison.md`) moved to `evaluation/archive/` rather than left mixed with current output |

## Remaining limitations (read before deploying)

1. **Quran audio is code-complete but still unverified against the live
   API.** No network path to any Quran API exists in this sandbox, in v12
   or v13. Set real `QF_CLIENT_ID`/`QF_CLIENT_SECRET` and test
   `backend/quran_api.py` live before trusting it.
2. **nanoGPT acceptance rate (22-23%) did not move** despite a fresh
   from-scratch retrain and a larger COMFORT_BANK (8→15/emotion). Read
   honestly, this points at the model's capacity/data scale as the actual
   ceiling, not at anything fixable by more curated targets alone. Brief
   sections 13-14 (tokenizer comparison, architecture-size experiment)
   were **not run this pass** for the same reason section 3 gave for the
   classifier not being retrained — but unlike the classifier, this IS the
   stated bottleneck, so this is a real gap, not a deliberate skip. A
   pretrained base model remains the most likely actual fix and remains
   blocked by network access here.
3. **`conversations_dataset_v13.json` is programmatically assembled**, not
   organically collected — see `data/multiturn_banks.py` for the exact
   method and its honest repetition profile (turn-2 lines repeat across
   conversations; turn-1 lines are all distinct real examples).
4. **Grouped train/val splitting by near-duplicate family (brief section
   15) was not implemented.** `model/prepare_corpus.py` still does a
   random row-level split. Not fixed this pass — flagged rather than
   silently left as-is.
5. **Classifier untouched, per the brief's own instruction** (section 3) —
   91% accuracy / 0.92 macro F1, same as v12. `evaluation/classifier_report.txt`'s
   header still says "v10" (stale label from an earlier pass, the
   underlying model is what both v12 and v13 actually use).
6. **Safety trigger list remains a small, disclosed-incomplete keyword
   list**, not a production crisis-detection model.
7. **Frontend still needs a locally-running backend** — no hosted server
   exists behind this prototype; this was not in scope to change.
